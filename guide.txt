1. WHAT WAS BUILT
================================================================================

A complete, production-ready personal portfolio website.

TECHNOLOGIES USED
-----------------

    Next.js 16          The website framework (React-based).
                        It builds the site into fast, static HTML pages.

    React 19            The library that builds the user interface.

    TypeScript          JavaScript with type checking. It catches mistakes
                        (like a misspelled field name) before the site runs.

    Tailwind CSS 4      The styling system. Colours, spacing and typography
                        all come from design tokens defined in one file.

    Framer Motion       Animation library. Used only where it is genuinely
                        needed: the command palette, the project drawer, the
                        mobile menu, the nav indicator and the scroll bar.

    Lucide React        The icon set.

There is NO database, NO backend server and NO paid service.
The whole site is static files, which is why it is fast and free to host.


WHAT THE WEBSITE CONTAINS
-------------------------

    Hero            Your name, your positioning, an animated diagram of the
                    DATA -> AI -> SOFTWARE -> CLOUD pipeline, and two buttons
                    (View My Work / Download CV).

    About (01)      Your photo, your story, your education and your languages.

    Experience (02) A timeline of your two internships (ONEE and IAWEB.DEV),
                    with the workstreams and technology stack of each.

    Projects (03)   One large featured case study (AgriSure AI) plus a grid of
                    the other projects. Clicking any card opens a full
                    case-study panel: The Challenge, The Solution,
                    Architecture, Key Features, Impact, Stack and links.

    Skills (04)     Your technologies grouped into six engineering domains.
                    Deliberately no percentage bars and no invented ratings.

    Achievements(05) The RAMADANIA 3rd place, Club IRISI, other competitions,
                    and your Oracle certification.

    Contact (06)    A large call to action, your email (click to send, or copy
                    to clipboard), your GitHub and LinkedIn, and a CV download.


FEATURES YOU MIGHT NOT NOTICE IMMEDIATELY
-----------------------------------------

    * Press Ctrl+K (or Cmd+K on a Mac) anywhere on the site. A search palette
      opens and you can jump to any section, project or link with the keyboard.

    * A dark/light theme switch in the top right. Your choice is remembered.

    * The navigation highlights whichever section you are currently reading.

    * The site works completely without JavaScript, and respects the
      "reduce motion" accessibility setting.

    * Everything is keyboard accessible and passes automated accessibility
      checks (0 violations, in both themes, on desktop and mobile).

3. REQUIREMENTS BEFORE RUNNING
================================================================================

You need three programs installed.

    Node.js     version 20.9 or newer   (this project was built on 20.18.3)
    npm         comes bundled with Node.js
    Git         to save and upload your changes

HOW TO CHECK WHAT YOU HAVE
--------------------------

Open a terminal and run these three commands, one at a time:

    node -v
    npm -v
    git --version

You should see something like:

    v20.18.3
    10.8.2
    git version 2.47.1

IF NODE IS MISSING OR TOO OLD
-----------------------------

Download the "LTS" version from:

    https://nodejs.org

Install it, close your terminal completely, open a new one, and run
`node -v` again.

If the number is BELOW v20.9.0, the project will not build. Upgrade before
continuing.

4. HOW TO RUN THE PROJECT LOCALLY
================================================================================

STEP 1 — Go into the project folder

    cd "/home/timsilo/Desktop/hussin/Portfolio repo"

STEP 2 — Install the libraries (only needed the first time, or after you
         pull changes that add a new library)

    npm install

    This downloads everything into a `node_modules` folder.
    It takes 1-3 minutes. It will print some warnings — that is normal.

STEP 3 — Start the development server

    npm run dev

    You will see something like:

        ▲ Next.js 16.3.4
        - Local:  http://localhost:3000

STEP 4 — Open the website

    Open your browser and go to:

        http://localhost:3000

    The site is now running on YOUR computer only. Nobody else can see it.

STEP 5 — Edit and watch it update

    Change any file in src/data/, save it, and the browser updates by itself.
    You do not need to restart anything.

STEP 6 — Stop the server

    Click on the terminal and press:  Ctrl + C


OTHER USEFUL COMMANDS
---------------------

    npm run build       Builds the real production version.
                        ALWAYS run this before pushing. If it fails, the
                        deployment on Vercel will fail too.

    npm run start       Runs the built production version locally
                        (run `npm run build` first).

    npm run lint        Checks the code for problems.

    npm run typecheck   Checks that all your data matches the expected shape.
                        Very useful after editing src/data/ files.

5. WHERE TO PUT MY PROFILE PHOTO
================================================================================

ALREADY DONE
------------
A profile photo has already been added for you. It was extracted from the photo
inside your own CV (CV1.pdf) and resized for the web.

    Current file:   public/images/profile/profile.jpg
    Current size:   1200 x 1500 pixels (about 200 KB)

You do not have to do anything. But if you want a BETTER photo, here is how.


HOW TO REPLACE IT
-----------------

    EXACT FOLDER:     public/images/profile/
    EXACT FILENAME:   profile.jpg
    (lowercase, with .jpg at the end — the name must match exactly)

    1. Prepare your new photo.
    2. Rename it to exactly:  profile.jpg
    3. Copy it into the folder  public/images/profile/
       replacing the file that is already there.
    4. Refresh your browser.

RECOMMENDED IMAGE SPECIFICATIONS
--------------------------------

    Shape           Portrait, taller than wide.
    Aspect ratio    4:5  (the site displays it in a 4:5 frame)
    Dimensions      1200 x 1500 pixels is ideal.
                    Do not go below 800 x 1000 (it will look blurry).
                    Do not go above 2000 x 2500 (pointlessly large file).
    Format          .jpg  (best for photographs)
    File size       Keep it under 400 KB. Under 250 KB is better.
    Framing         Head and shoulders, face roughly in the upper middle.
                    The site darkens the bottom of the photo slightly, so
                    do not put anything important down there.

IF YOU WANT TO USE A DIFFERENT FILENAME
---------------------------------------

Open:  src/data/personal.ts
Find:  profileImage: "/images/profile/profile.jpg",
Change the text inside the quotes to your filename, for example:

    profileImage: "/images/profile/abdedaym.jpg",

Note the path always starts with  /images/  (NOT  /public/images/).

IF THE PHOTO IS MISSING
-----------------------

Nothing breaks. The site automatically shows an elegant placeholder with your
initials ("AC") on a gradient. You will never see a broken image icon.

6. WHERE TO PUT PROJECT SCREENSHOTS
================================================================================

RIGHT NOW
---------
No screenshots are needed. Every project card currently shows original
generated artwork that was designed specifically for that project — an NDVI
satellite raster for AgriSure AI, a Kubernetes cluster diagram for TaskMaster,
a message-classification flow for Mindkeeper, and so on.

These look good on their own. Adding a real screenshot is an UPGRADE, not a
requirement.


HOW TO ADD A SCREENSHOT
-----------------------

    EXACT FOLDER:  public/images/projects/

    STEP 1 — Take the screenshot of your running project.

    STEP 2 — Name it after the project, in lowercase with dashes:

                 agrisure.png
                 ecommerce.png
                 taskmaster.png
                 mindkeeper.png
                 ai-system-designer.png
                 fstracker.png

    STEP 3 — Put the file in  public/images/projects/

    STEP 4 — Connect it to the project.

             Open:  src/data/projects.ts
             Find the project you want (search for its name).
             You will see a line that is "commented out" like this:

                 // image: "/images/projects/agrisure.png",

             Remove the two slashes at the start so it becomes:

                 image: "/images/projects/agrisure.png",

             Save the file. The screenshot now replaces the generated artwork.

    STEP 5 — Refresh the browser and check it.

RECOMMENDED SCREENSHOT SPECIFICATIONS
-------------------------------------

    Aspect ratio    16:10 for the grid cards, 16:9 for the featured card.
                    Anything close is fine — the site crops to fit.
    Dimensions      1600 x 1000 pixels is ideal.
                    Minimum 1200 x 750.
    Format          .png for interfaces (sharp text), .jpg for photos.
    File size       Under 500 KB each. Compress at https://squoosh.app
                    if yours are larger.
    Content         Show the most impressive screen. Avoid empty states,
                    lorem ipsum, and anything with real personal data in it.

IF A SCREENSHOT IS MISSING OR BROKEN
------------------------------------

The site silently falls back to the generated artwork. It never breaks.

HOW TO UPDATE YOUR CV LATER
---------------------------

    EXACT FOLDER:     public/documents/
    EXACT FILENAME:   Abdedaym-Chakra-CV.pdf
                      (capital A, capital C, with the dashes — exactly this)

    1. Export your new CV as a PDF.
    2. Rename it to exactly:  Abdedaym-Chakra-CV.pdf
    3. Copy it into  public/documents/  replacing the old one.
    4. Refresh the browser and click "Download CV" to test it.

IF YOUR PDF IS LARGER THAN 1 MB
-------------------------------

Compress it first. On Linux, with ghostscript installed:

    gs -sDEVICE=pdfwrite -dCompatibilityLevel=1.5 -dPDFSETTINGS=/ebook \
       -dNOPAUSE -dQUIET -dBATCH -sOutputFile=cv-small.pdf your-cv.pdf

Or use a free online tool such as https://www.ilovepdf.com/compress_pdf

HOW THE DOWNLOAD BUTTON WORKS
-----------------------------

There are three "Download CV" buttons on the site: in the hero, in the contact
section, and inside the Ctrl+K command palette. All three read the same two
settings from  src/data/personal.ts :

    cvPath:     "/documents/Abdedaym-Chakra-CV.pdf",
    cvFileName: "Abdedaym-Chakra-CV.pdf",

  cvPath      = where the file lives (always starts with /documents/)
  cvFileName  = the name the visitor's browser suggests when saving

If you change the filename in the folder, change BOTH of these lines to match.

This works identically on your computer and on Vercel — the PDF is just a
static file served straight from the public folder.

9. HOW TO ADD OR EDIT PROJECTS
================================================================================

FILE TO EDIT:   src/data/projects.ts

Each project is one block between  {  and  },  inside the big list.

TO EDIT AN EXISTING PROJECT
---------------------------
Search for its name (for example "TaskMaster"), and change the text.

TO ADD A NEW PROJECT
--------------------
Copy an entire existing block (from its opening `{` to its closing `},`),
paste it, and change every value. Here is what each field means:

    id:         A unique short name, lowercase with dashes.
                Used internally. Must not repeat.
                Example:  "weather-api"

    name:       The project title shown on the card.
                Example:  "Weather API"

    subtitle:   One line, shown in blue under the title.
                Example:  "Forecast aggregation across three providers"

    domain:     The category label above the title.
                Example:  "Backend & Data"

    status:     MUST be one of exactly these four:
                    "Production"
                    "Award Winner"
                    "Personal Project"
                    "In Development"

    year:       "2026"

    award:      OPTIONAL. Delete this line if there is no award.
                Example:  "1st Place — Some Hackathon"

    summary:    1-2 sentences. Shown on the card.

    challenge:  The problem, in 2-4 sentences. Shown in the case study.
                Write about WHY it was hard, not just what it was.

    solution:   How you solved it, in 2-4 sentences.

    architecture: A LIST of technical bullet points. One string per line:
                  [
                    "First technical point",
                    "Second technical point",
                  ]

    features:   A LIST of what the product does, one string per line.

    impact:     One or two sentences on the result.
                >>> Do NOT invent numbers or metrics you cannot back up.

    stack:      A LIST of technology names shown as small chips.
                  ["Python", "FastAPI", "PostgreSQL"]

    visual:     Which generated artwork to draw. MUST be one of exactly:
                    "satellite"       NDVI / geospatial raster
                    "commerce"        product cards and a revenue chart
                    "orchestration"   Kubernetes-style cluster grid
                    "agent"           AI message classification flow
                    "architecture"    API / queue / workers / databases
                    "vision"          computer-vision detection brackets

    image:      OPTIONAL. See section 6.

    links:      OPTIONAL. Buttons only appear for links you actually provide,
                so there are never dead links on your site.

                  links: {
                    github: "https://github.com/CHAKRAbdedaym/your-repo",
                    demo:   "https://your-demo.vercel.app",
                  },

                >>> IMPORTANT: right now NO project has links, because no
                    repository URLs were available when the site was built.
                    Adding your GitHub links is the single highest-value
                    improvement you can make. Recruiters click them.

    featured:   true or false.
                >>> EXACTLY ONE project must be true. It gets the big card at
                    the top. Currently that is AgriSure AI.
                    If you set a second one to true, only the first is used.

AFTER EDITING
-------------
    npm run typecheck

TypeScript will tell you immediately if you used an invalid `status` or
`visual` value, or forgot a required field.

11. HOW TO ADD NEW SKILLS
================================================================================

FILE TO EDIT:   src/data/skills.ts

There are three separate lists in this file.

--------------------------------------------------------------------------------
A) TO ADD A TECHNOLOGY TO AN EXISTING DOMAIN
--------------------------------------------------------------------------------

This is what you will do 95% of the time.

Find the domain, then add your technology to its `items` list.
For example, to add "Kafka" to the data domain:

    {
      id: "data",
      name: "Data & Databases",
      ...
      items: [
        "PostgreSQL",
        "MySQL",
        "MongoDB",
        "Kafka",              <-- add this line
      ],
    },

Do not forget the quotes and the comma.

--------------------------------------------------------------------------------
B) TO ADD A WHOLE NEW DOMAIN CARD
--------------------------------------------------------------------------------

Copy an entire domain block and change:

    id:           Unique short name.  "security"
    name:         "Security Engineering"
    description:  One sentence about how you use this domain in practice.

    icon:         MUST be one of exactly these words:
                      "brain"      a brain      (AI / ML)
                      "server"     a server     (backend)
                      "layout"     a layout     (frontend)
                      "cloud"      a cloud      (cloud / devops)
                      "database"   a database   (data)
                      "wrench"     a wrench     (tools)
                      "code"       code brackets (general)

                  These are the only values that work. If you need a different
                  icon, it has to be added to  src/lib/icons.ts  first.

    accent:       MUST be one of:  "blue"  "indigo"  "cyan"  "violet"
                  This sets the colour of the icon and the hover glow.

    items:        The list of technologies.

--------------------------------------------------------------------------------
C) THE TWO SMALLER LISTS AT THE BOTTOM OF THE FILE
--------------------------------------------------------------------------------

    languagesUsed     The programming languages that scroll across the screen
                      in a moving strip above the domain cards.
                      Just a simple list of names.

    spokenLanguages   Arabic / French / English, shown in the About section.
                          { name: "Spanish", level: "Basic", strength: 1 }
                      `strength` must be 1, 2 or 3. It draws that many filled
                      dots out of three. It is NOT a percentage and it is not
                      labelled as one.

--------------------------------------------------------------------------------
A NOTE ON HONESTY
--------------------------------------------------------------------------------

This section is deliberately titled "The technologies and domains I work with",
not "My skills at 95%". There are no progress bars and no star ratings, because
experienced engineers and recruiters both distrust them. Keep it that way — a
long honest list is far more credible than a short list of fake 90% bars.

CERTIFICATIONS

13. ENVIRONMENT VARIABLES
================================================================================

>>> THIS PORTFOLIO DOES NOT REQUIRE ENVIRONMENT VARIABLES FOR THE CORE
    FUNCTIONALITY.

You can run it, build it and deploy it to Vercel without setting a single one.
There are no API keys, no secrets, and no external services.

THE ONE OPTIONAL VARIABLE
-------------------------

    NEXT_PUBLIC_SITE_URL

    What it does:
        Tells the site its own public address. This address is used for:
          - the canonical link tag (tells Google which URL is the real one)
          - the Open Graph tags (the preview card when you share the link)
          - sitemap.xml and robots.txt

    Do I need it?
        NO, if you use the free address Vercel gives you
        (something like my-portfolio.vercel.app). Vercel automatically
        provides the address and the site picks it up on its own.

        YES, if you buy a custom domain such as abdedaym.dev. Then set it so
        that Google indexes the right address.

    Values to use:
        Local development:   leave it empty (defaults to http://localhost:3000)
        Production:          https://your-actual-domain.com
                             (no trailing slash at the end)

HOW TO SET IT LOCALLY
---------------------

    1. In the project folder, copy the example file:

           cp .env.example .env.local

    2. Open  .env.local  and fill in the value:

           NEXT_PUBLIC_SITE_URL=https://abdedaym.dev

    3. Stop the dev server (Ctrl+C) and start it again with `npm run dev`.
       Environment variables are only read at startup.

>>> NEVER commit .env.local to Git. It is already listed in .gitignore, so
    Git will ignore it automatically. Do not remove that line.

HOW TO SET IT ON VERCEL
-----------------------

    1. Go to your project on vercel.com
    2. Settings  ->  Environment Variables
    3. Key:    NEXT_PUBLIC_SITE_URL
       Value:  https://your-actual-domain.com
       Environments: tick Production (and Preview if you like)
    4. Save.
    5. Go to the Deployments tab and click "Redeploy" on the latest
       deployment. Environment variables are only applied at BUILD time, so an
       existing deployment will not pick up the new value on its own.

>>> THE GITHUB REPOSITORY ALREADY EXISTS AND IS ALREADY CONNECTED TO THIS

    You do NOT need to create a repository.

Run:

    origin  git@github.com:CHAKRAbdedaym/My_Portfolio.git (fetch)

---------------------------

    git status

    - Files in RED are changed but not yet saved to Git.
    - Files in GREEN are staged, ready to be saved.
    - "nothing to commit, working tree clean" means everything is saved.

            git commit -m "content: update availability to March 2027"

        Uploads to GitHub. This is what triggers a new deployment.

    Do NOT run `git remote add origin ...` — the remote already exists.
    Do NOT create a second repository on GitHub.

16. AUTOMATIC DEPLOYMENTS
================================================================================

After the first deployment, you never need to touch the Vercel dashboard again.

HERE IS WHAT HAPPENS AUTOMATICALLY
----------------------------------

    You edit a file on your computer
                 |
                 v
    git add .    and    git commit -m "your message"
                 |
                 v
    git push
                 |
                 v
    GitHub receives the new code
                 |
                 v
    GitHub notifies Vercel automatically
                 |
                 v
    Vercel runs  npm install  and  npm run build
                 |
                 v
    If the build SUCCEEDS  ->  your live website is updated (1-2 minutes)
    If the build FAILS     ->  your live website STAYS ON THE OLD VERSION
                               and Vercel emails you the error

    That last point is important and reassuring: a broken build can never take
    your live site down. The old version keeps serving until a new build
    succeeds.

BRANCHES
--------

    Pushing to the  main  branch     ->  updates your PRODUCTION website.
    Pushing to any other branch      ->  creates a temporary PREVIEW website
                                         at its own URL, without touching
                                         production. Useful for trying a big
                                         redesign safely.

>>> This is why you should ALWAYS run  npm run build  locally before pushing.
    If it fails on your computer, it will fail on Vercel too.

A custom domain means an address like  abdedaym.dev  instead of

19. TROUBLESHOOTING
================================================================================

--------------------------------------------------------------------------------
PROBLEM: `npm install` fails
--------------------------------------------------------------------------------

  Try, in order:

    1. Check your Node version:
           node -v
       It must be 20.9.0 or newer. If it is older, install a newer Node.

    2. Delete everything and reinstall from scratch:
           rm -rf node_modules package-lock.json
           npm install

    3. Clear the npm cache:
           npm cache clean --force
           npm install

    4. Check your internet connection. npm downloads about 370 packages.

--------------------------------------------------------------------------------
PROBLEM: `npm run dev` fails
--------------------------------------------------------------------------------

  "Error: listen EADDRINUSE: address already in use :::3000"
      Something else is already using port 3000 — probably a dev server you
      forgot to stop. Either close it, or run on a different port:
           PORT=3001 npm run dev
      then open http://localhost:3001

  "Cannot find module ..."
      You have not installed the libraries yet:
           npm install

  The page loads but is completely blank
      Open the browser console (press F12, then the "Console" tab) and read
      the red error. It usually names the file and line.

--------------------------------------------------------------------------------
PROBLEM: `npm run build` fails
--------------------------------------------------------------------------------

  Read the error message carefully — it names the FILE and the LINE NUMBER.

  "Type error: Property 'xyz' is missing in type ..."
      You added an entry to a data file but left out a required field.
      Compare your new block against an existing one — something is missing.

  "Type error: Type '"foo"' is not assignable to type ..."
      You used a value that is not allowed. This happens with:
          status:  must be "Production" | "Award Winner" |
                          "Personal Project" | "In Development"
          visual:  must be "satellite" | "commerce" | "orchestration" |
                          "agent" | "architecture" | "vision"
          kind:    must be "enterprise" | "startup"
          icon:    see sections 11 and 12 for the allowed values
      The error message lists the allowed values. Use one of them exactly.

  "Unexpected token" / "',' expected"
      A punctuation mistake in a data file: a missing comma at the end of a
      line, a missing closing quote, or a missing } or ].

  Quick check without a full build:
      npm run typecheck
  This is much faster and finds the same data errors.

--------------------------------------------------------------------------------
PROBLEM: Images do not appear
--------------------------------------------------------------------------------

  1. Check the path in the data file starts with  /images/
     and NOT with  /public/images/  or  ./images/

         RIGHT:  "/images/projects/agrisure.png"
         WRONG:  "/public/images/projects/agrisure.png"

  2. Check the filename matches EXACTLY, including capital letters.
     On Linux and on Vercel,  Photo.JPG  and  photo.jpg  are different files.
     This is the single most common cause, and it is nasty because it often
     works on Windows and then breaks on Vercel.

  3. Check the file is actually in the folder:
         ls public/images/projects/

  4. Remember: a missing image is NOT a bug here. The site is designed to fall
     back to the generated artwork (projects) or a monogram (profile photo).
     If you see the fallback, the file is missing or misnamed.

--------------------------------------------------------------------------------
PROBLEM: The CV download does not work
--------------------------------------------------------------------------------

  1. Check the file exists:
         ls public/documents/

  2. Check the name matches  cvPath  in  src/data/personal.ts  EXACTLY,
     capital letters included.

  3. Test the URL directly in your browser:
         http://localhost:3000/documents/Abdedaym-Chakra-CV.pdf

--------------------------------------------------------------------------------
PROBLEM: Environment variables missing / not applied
--------------------------------------------------------------------------------

  Locally:
      The file must be named exactly  .env.local  (starting with a dot).
      You must restart `npm run dev` after changing it.

  On Vercel:
      Variables are applied at BUILD time, not at page-load time. After adding
      or changing one you MUST redeploy:
          Deployments -> the three dots on the latest one -> Redeploy

  Also: only variables whose name starts with  NEXT_PUBLIC_  are visible to
  the browser. That is a security feature, not a bug.

--------------------------------------------------------------------------------
PROBLEM: The Vercel deployment fails
--------------------------------------------------------------------------------

  1. Read the build log on Vercel. Click the failed deployment, then
     "Building". The error is the same one you would see locally.

  2. Reproduce it on your own machine:
         npm run build
     Fix it there, then commit and push again.

  3. If it builds locally but fails on Vercel:
       - Check the Node.js version in Vercel Settings -> General.
         It must be 20.x or newer.
       - Check for filename capitalisation problems (see the images section
         above). This is the classic "works on my machine" failure.
       - Make sure you actually pushed. Run `git status` — if it says you have
         unpushed commits, Vercel is still building your OLD code.

--------------------------------------------------------------------------------
PROBLEM: `git push` fails
--------------------------------------------------------------------------------

  "Permission denied (publickey)"
      Your computer cannot prove to GitHub who you are. The repository uses
      SSH. Either:

        (a) Set up an SSH key — follow GitHub's guide:
            https://docs.github.com/en/authentication/connecting-to-github-with-ssh

        (b) Or switch the repository to HTTPS, which asks for a token instead:
            git remote set-url origin https://github.com/CHAKRAbdedaym/My_Portfolio.git
            Then push. When prompted for a password, use a Personal Access
            Token from GitHub -> Settings -> Developer settings, NOT your
            account password.

      Test whether SSH is working at all:
            ssh -T git@github.com
      Success looks like: "Hi CHAKRAbdedaym! You've successfully
      authenticated..."

  "Updates were rejected because the remote contains work that you do not
   have locally"
      Someone (or you, from another computer, or GitHub's web editor) changed
      the repository. Bring those changes down first:
            git pull --rebase
            git push

  "fatal: not a git repository"
      You are in the wrong folder. cd into the project folder first.

--------------------------------------------------------------------------------
PROBLEM: Wrong GitHub remote
--------------------------------------------------------------------------------

  Check what is currently set:
        git remote -v

  It must show:
        origin  git@github.com:CHAKRAbdedaym/My_Portfolio.git (fetch)
        origin  git@github.com:CHAKRAbdedaym/My_Portfolio.git (push)

  If it points somewhere else, correct it WITHOUT creating a new repository:
        git remote set-url origin git@github.com:CHAKRAbdedaym/My_Portfolio.git

  Then verify again with  git remote -v.

--------------------------------------------------------------------------------
PROBLEM: The site looks wrong after I changed a colour
--------------------------------------------------------------------------------

  All colours live in  src/app/globals.css , at the very top, in two blocks:

        :root         { ... }    the DARK theme (the default)
        :root.light   { ... }    the LIGHT theme

  If you change a colour in one block, change the matching one in the other,
  or the light theme will break.

  If you make text lighter, check it is still readable. The rule is a contrast
  ratio of at least 4.5:1 against the background. Test yours at:
        https://webaim.org/resources/contrastchecker/

--------------------------------------------------------------------------------
PROBLEM: I broke something and I want to undo it
--------------------------------------------------------------------------------

  Undo changes to ONE file that you have NOT committed:
        git checkout -- src/data/personal.ts

  Undo ALL uncommitted changes (careful — this cannot be undone):
        git checkout -- .

  See your history of saved versions:
        git log --oneline

  Go back and look at an older version (read-only):
        git checkout <the-short-code-from-git-log>
  and come back to the present with:
        git checkout main
